# TUI campaign: first source unit

2026-10-15. The operator authorizes the campaign and explicitly selects Microsoft
tui-test plus Neovim-style screen expectations alongside usual rigor. Stable
presentation, including understood imperfections, is deliberately baselined.

This source unit owns:

- [Microsoft adoption](adoption/PLAN.md), [results](adoption/RESULTS.md), [original manifests](adoption/MANIFEST.tsv)
  and [tooling](../../tooling/TUI_TESTING.md): pinned development-only release,
  explicit installer/launcher and actual Blackbird emulator scenarios.
- [Readable snapshot plan](snapshots/PLAN.md) and [results](snapshots/RESULTS.md):
  eleven deterministic styled cells/cursor/state fixtures at actual public
  rendering/input seams, explicit updates and readable failure artifacts.
- [Native component subplan](components/SUBPLAN.md): keyed immutable scene
  publication, checked handles, collection selection/anchor/focus, draft CAS and
  deliberately armed target references, without domain execution authority.
- [ESC recovery plan](input/SUBPLAN.md) and [results](input/REPORT.md): expired
  lone/incomplete prefixes cannot swallow later ready input, while active literal
  paste and supported legacy controls retain their semantics.

These native primitives are the beginning of arconaut-rhi.3, not the whole native
host, Lua composition worker, action bridge or command center. Existing product
views have not been migrated to a new component framework in this unit.

Microsoft Ghostty/Alacritty backends exercise VT engines and generated artifacts;
no actual GUI/font/GPU/device or broad responsiveness result is claimed. Provider
requests are absent from the controlled local fixtures. Native/fault/PTY/custody,
sanitizer/source/profile checks remain independent requirements.

One bounded independent code challenge is recorded under review/. Source gate and
affected-platform results are recorded in QUALIFICATION.md when complete. No
review of reviews, new evaluator, mutation fleet or native hot activation.
