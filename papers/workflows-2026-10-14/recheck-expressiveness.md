**Disposition: F1–F5 resolved in the design; F6 illustration supplied.** These are specification dispositions, not implementation qualification.

| Finding | Remedy checked | Disposition |
| --- | --- | --- |
| F1: old-input work publishes after demand invalidation | Result/publication eligibility includes run/demand, node/result, exact input/context revisions and publication epoch. Invalidation revokes current eligibility before replacement admission. Internal publication and external release recheck it; old results stay in their old lineage, and dispatched effects remain real obligations. The direct oracle explicitly rejects old-demand join qualification. | Resolved. Same worker generation and unchanged target base no longer suffice to publish stale work. |
| F2: open expansion and join closure conflated | Expansion membership revisions and producer close/abort records are independent. Joins cannot close shared producers implicitly. Final all/collection require closure; early selection freezes its own winners, later members need separate observation/control. Impossibility uses final outcomes plus closed membership or finite bounds. Retry/retraction create successor revisions; predicates are pure or recorded. | Resolved. One early quorum no longer silently closes another observer or reaches future children. |
| F3: authored shared application state lacks atomic semantics | Typed revisioned cells use consistent planning snapshots/read sets and bounded expected-revision multi-cell changes within the existing transaction. Stale plans reject without effects. Recorded-command reads/updates use that surface. Fork policies distinguish as-of, current-at-fork, fresh and explicit live sharing; atomicity stops at the owner boundary. | Resolved. Concurrent plan changes, inbox consumption and task/effect admission have a defined internal atomic boundary. |
| F4: recovery/recreation identity ambiguous | Normal recovery preserves logical actor/run/node/invocation and accepted inbox endpoints while changing execution incarnation/owner epoch. Stop-incarnation differs from retire-actor; retirement tombstones block automatic revival. Explicit successor creation declares transferred inbox/waits/unresolved observations; names never transfer replies implicitly. | Resolved. Accepted messages and existing waits survive normal recovery without reviving retired actors. |
| F5: reservation lifetimes ambiguous at nested awaits | Metadata separates runnable occupancy, request-local settlement, ongoing-effect custody/cleanup and leases with named users. Suspension returns only ended occupancy. Nested model work gets its own shared-root grant; held-set/live-user conflicts return release/transfer/split alternatives. Scheduler waits return the physical pool worker, with explicit limits for nonresumable blocking adapters. | Resolved. A parent can yield capacity without dropping a writing child's lease or blocking its children on the same pool. |
| F6: missing complete imperative example | The new proposed Lua function performs nested durable discovery, keyed participant expansion, explicit closure, typed quorum observation, loser cancellation, integration/testing, checked artifact publication and scope close/settlement. The surrounding text states parking, wait cancellation, retained keys/results and stale-publication conflict behavior. | Supplied. Exact binding spelling remains an implementation decision, as expressly stated; the composition is now reviewable. |

No additional required repair was found within this recheck scope. The specification can return to operator discussion and implementation planning. Product claims still depend on the owning delivery units and direct oracles already named in the design.
