## PX1: external JSON is acquired before its original is published

The pre-encode DATA grant is necessary but does not publish the encoder result.
Compatibility openai_http obtains its successful dump_json output, then calls
config_quote and allocates/appends the curl configuration before trace.body copies
that original. An allocation failure in the quote/append interval destroys the
unpublished external request bytes. The terminal honestly says allocation, but
the original the encoder already returned is absent.

ProviderAuth::request likewise returns dump_json inside ProviderHttpRequest
construction and subsequently allocates headers/authorization text before
provider_http_impl creates its trace and publishes the body. Inside the ordinary
native provider_http_impl, construction/quoting of input and headers also precedes
trace.body, although the existing request already owns its body. These intervals
contradict the reviewed immediate acquisition-to-publication order.

Publish the one acquired external body immediately after its existing encoder
returns and before any further fallible header/configuration construction. Stage
the actual HTTP request trace and its complete terminal/checked DATA bank before
that encoder, and pass that same explicit trace into the downstream synchronous
HTTP implementation where needed. Publish each existing1301 body once; preserve
actual auth-resolution and request/receipt links. For provider_http with an
already acquired request, publish its body before constructing private curl
configuration. Do not adopt a second encoder, new role dictionary, callback,
storage service or duplicate full original as an easier substitute.

Execute actual baseline reds for compatibility encoding and owned public request
encoding. Cut a real allocation after the complete expected external JSON already
exists and before quote/header construction completes. An allocator observer can
identify that literal live encoded buffer using independent expected bytes; its
next allocation refusal must be genuine. Check actual allocation failure,
undispatched native child/injection, missing body on the old candidate, then exact

Keep the independent full-body oracle, not just event presence. Test the ordinary
