## Common source-unit protocol (later, never run here)

2. Write fault-specific old-behavior RED and unchanged expected semantics before fixing. If current code already passes a subcase, record capability, not fake RED. Proposed REDs below are obligations, **not observed test failures**. 3. Implement owner publications/state before exposing a label/action that depends on them. Missing relation stays unavailable. Extend shared native/Lua primitives only as required by the task, retaining owned native values and minimal capture.
4. Per source unit: layer1 fix/remediation + direct checks; layer2 one focused recheck/fix. These later allowances are separate from this design unit, never a third design review. Declare tasks before work, no invented wall timer/request ceiling or silent reset. No reviews of reviews; unsafe blockers at bound remain inactive.
5. Required source Debug/full clean lint gate via normal `.githooks/pre-commit` / `scripts/rigor check debug`, relevant direct semantic/fault/PTY/readable-screen checks, qualified Release and ordinary Linux Debug/Release/ASan profiles under `scripts/check-linux` as required by current source instructions. Serialize builds/checks through absolute `ROOT/with-build-slot.py` (read its usage at commission); do not bypass source hook. Pin/provision adopted Microsoft dev tool explicitly on fresh hosts; no tests downloading tooling implicitly. Recheck changed paths rather than unrelated settled suite repeats. No laptop mutants/AFL campaign/eval/assurance family to certify this prose.
6. Every tranche comparison uses the performance protocol below. Commit/push normally only after actual requirements pass; retain logs/failed fixture dirs and exact remote ref readback. Never blindly repeat uncertain writes or kill healthy jobs for silence. Reconcile owned children/participant runs; unknown remains unknown, not exit0-derived safety.

### Distinct evidence levels

- **Task semantics:** intention/turn/request identities and transitions, actual owner result/effect outcome, resource refusal and unknown recovery.
- **Source capability:** direct native public API/fault/lifetime/admission tests; does not prove physical interaction.
- **Physical PTY:** actual input bytes, split sequences, blocked output EAGAIN, resizing, target identity and independent child/provider/control ledgers. VT traces are not GUI/keyboard hardware observation.
- **Readable screens:** reviewed component cells/styles/cursor and real main-process VT captures at wide/narrow/dense/tiny geometries. A screenshot cannot prove control service or request inclusion.
- **Safe provider fixtures / live observation:** fake transport can establish local request/inclusion/race behavior, not remote provider stop. Live provider probes need explicit safe scope and recorded transport/outcomes; no auth changes or operator-session interference.
- **Actual expert task study:** a real expert's completed task, errors/compensation and fluency; neither a fixture nor these authored mockups substitute for it. Unobserved conditions stay explicit obligations.
