# Behavioral contracts

Normative proposed behavior, not implemented APIs. C1–C9 link to [actual/proposed owners](OWNERS.md); R1–R10 refer to the accepted [requirements](../chat-usability-2026-10-27/REQUIREMENTS.md). Each distinction must be supported by owner publication, never inferred from color, time or absent rows. Short IDs below are session-unique display aliases for full identities available in detail.

## C1 — Compose, send, establish receipt (R2, R8, R10)

Composer is native local text/cursor/history. Enter deliberately submits; Ctrl-J always inserts newline in harness composer. Modified Enter hints appear only for the effective terminal profile; don't rely on Shift-Enter. Bracketed paste, recalled text and IME composition remain literal until Send. Existing deliberate slash/bare/POWERWORD grammar remains; no redraw or pasted control fires a workflow. Unknown slash remains local error. A locally executed command receipt names that route; it is not a message supposedly delivered to a model.

Allocate a stable intention identity at deliberate Send acquisition, before clearing draft. Record immutable submitted bytes plus revision, input origin and route. Two Enter actions with equal text allocate two identities. Repaint/replayed observation of the same identity does not allocate one. Keep submitted bytes recoverable if later acceptance fails. Short receipt and selected exact text appear in current shelf immediately, without waiting for worker or provider. On terminal-output blockage, no promise of a visible acknowledgment before drain: the native owner can acquire/process while the old packet remains pending.

| Receipt label | Exact meaning and owner evidence | Failure/unknown handling |
| --- | --- | --- |
| Sending locally | Terminal acquired Send; acceptance not yet established | Retain text and ID; never “not sent” merely for absent acknowledgment. |
| Queued · next turn | Terminal queue accepted this intention; runnable after current turn | Queue save/publication failure holds dispatch and keeps draft/recoverable receipt. |
| Starting · turn t | Worker launch accepted for this ID, not evaluation or provider dispatch | Separate launch refusal known not started; missing later observation remains last-known. |
| In context · revision c | CodingEngine/ContextStore accepted the objective as a user entry | Inline /lua is program execution, not the same user-entry inclusion. |
| Request q · attempt a | Provider request assembly/dispatch references actual context revision and inclusion relation | Only show “included in q” when the relation is established. No “read”, comprehension or universal remote delivery badge. |
| Turn completed / failed / interrupted | Main worker observed terminal result for t | Scope is turn only; attach consequential tool unknowns and remaining children/participants. |
| Not accepted · not started | Actual admission/refusal before launch | Restore recoverable text, resource/cause and inspect action. A retention failure after effect cannot use this label. |
| Receipt unresolved | Possible acceptance without reconcilable result | Show last-known ID/evidence, Inspect; no auto-send or new identity to hide uncertainty. |

Current shelf is keyed, bounded and paged. Latest submitted receipt stays adjacent to composer until another Send or explicit shelf navigation; historical receipt remains in transcript or retained receipt detail. A delayed owner result updates the same referent. Context edits may remove an objective before a request: show “not included in q” only from actual assembly, otherwise “inclusion unavailable”. A request may include several earlier objectives; don't imply one-to-one turn/request mapping. Tool IDs, provider attempt IDs, receipt IDs and direction IDs remain different.

Proposed receipt continuity belongs to TerminalUI/SessionStore and CodingEngine relations, not a UI-only database promising delivery. On crash between queue removal and launch, reopen says “previously accepted; launch/result not established” if that is all retained state supports; never auto-runs. A proposed native binary receipt record augments existing saved UI state without changing durability policy. If the owner cannot recover a relation, show unavailable rather than infer it from identical text. No universal exactly-once external effect guarantee.

## C2 — Correct pending work and choose next turn versus direction (R2, R3)

Queue shelf always says **Next turns**, not Steer. `/queue` opens that current keyed shelf; old textual listings are marked historical. Selecting an item reveals its full text/ID/status; actions are Edit, Hold, Send next, Withdraw to drafts. Native queue owner serializes acquisition against launch by exact ID+revision. Enter in queue navigation opens detail; only explicitly labeled Send next admits execution. Space/action buttons are not overloaded with composer Send.

Edit atomically moves a still-queued item to held editing state; it cannot launch while edited. Existing unsent composer is saved to recoverable drafts before loading, with cursor retained. If save fails, don't replace it. Apply correction creates an immutable text revision under the same intention with prior bytes retained; explicitly Resume returns it to runnable position. Discard edit restores held prior version, not runnable automatically. If launch won the race, refuse correction with actual turn link and keep proposed text as draft; do not mutate the running objective. Withdraw preserves text in drafts and marks receipt withdrawn, not canceled remote work. Reordering can initially be omitted; explicit Send next selects a held item, preserving other held items.

Stop holds all runnable next-turn items, retaining identities/order/text; no item automatically starts after stopping. This intentionally replaces current Ctrl-C queue-clearing behavior and must be announced in effective help. Resume selected/all is deliberate. Reopen converts queued/held work into recovered drafts requiring explicit Send, retaining predecessor reference; loading a recovered draft is not submission. A deliberate new Send creates a fresh intention linked to its predecessor, not replay of old effects.

Addressed participant direction uses run_id/message_id/from/text and next request boundary semantics (C7), never the main queue. No main live-steer action is advertised. Ordinary agency still permits stopping and sending a new instruction; the UI says which of those it did.

## C3 — Escape is usable main-turn stop (R1, R3, R8)

**Named action `turn.stop`: request cancellation of the main turn captured at input acquisition; preserve every draft/editor buffer/selection and hold next-turn queue. Cancellation is not undo.** It does not stop all participants or earlier background jobs. Actual foreground-cancel behavior remains owner-defined: ordinary exec cancellation stops its command; canceling a later foreground wait releases that wait without terminating the existing job. Show the exact affected turn and any associated command, not “stop everything”.

| Input scope | Bare ESC | Other reachable control / conflict resolution |
| --- | --- | --- |
| Harness composer, palette, view picker, modal form, selection, inspector, authored view | If main turn active: turn.stop has native priority over local dismissal. Keep local buffers and route, show stop receipt in shell. If no active turn: Back one local layer; in plain composer no destructive effect | Ctrl-C is the same turn.stop in harness modes, no palette swallowing. Ctrl-G is local Back/dismiss regardless of active turn; explicit route toggle also returns. Selection is retained on stop, cleared only by local action. |
| Startup question | No active turn: Back leaves required question unresolved; cannot bypass inference fence | Ctrl-J newline only where editable; valid choice explicitly answers, no default guessed. |
| Foreground private PTY input | Literal ESC to selected child/epoch; Ctrl-C literal03, Ctrl-X literal18. Do not steal terminal editing | Existing Ctrl-B detaches to harness composer, preserving draft; then ESC/Ctrl-C stops captured main turn if still active. Banner always says `PTY input j · Ctrl-B return; then Esc stop turn`. Explicit job stop is available after return for the child itself. |
| External editor | Editor owns its keys; ESC not harness stop | Launch remains idle-only. Return via editor's normal save/exit; failed handoff preserves draft. No claim to intercept editor keys. |
| Bracketed paste / terminal protocol | Literal contents; ESC inside paste never stop | Decoder resolves supported sequences first. Only an isolated decoded ESC after existing finite prefix deadline becomes turn.stop. Incomplete mouse/key tails cannot become text or a cancel cascade. |

Legacy ESC prefix ambiguity is unavoidable: Alt combinations may arrive as ESC+text; fragmented bytes past the declared decoder deadline can be ambiguous. Keep existing bounded-prefix recovery, expose effective encoding/deadline in `/keys`, test split sequences and literal paste. Ctrl-C after Ctrl-B is the unambiguous byte fallback; no double-ESC timing game. A host escape cannot function inside a blocked or lost terminal channel; external emergency signals remain outside this design's guaranteed key service.

Stop receipt: `Stop requested · t12 · queue held 2`. Native token captures t12 so delayed handling cannot stop t13. Repeated requests for the same active t are idempotent local control requests; do not signal a newly launched job by remembered PID. Stop at idle says no active turn; held queue remains held. Completion racing stop yields `t12 completed; stop arrived after completion` when owner order establishes it, or `completed; stop request also recorded` where ordering cannot be resolved. Never overwrite observed success with fake interruption.

Later terminal observation says `Turn interrupted locally` only on engine result; list command child settlement separately. Provider transport closed locally does not prove remote request stopped. Native blocked work says `Stop requested; worker has not returned · last observed: program source retention`, only where that frontier is published. Otherwise `last phase unavailable`. No arbitrary timeout turns silence into stopped; no kill of healthy workers merely for silence. Original outputs/effects remain inspectable; explicit independent work may proceed only where existing recovery fences permit.

## C4 — Typed compact tools and linked originals (R4, R5, R7)

Each call has one keyed card nested under its originating turn. Header is one physical argument row plus identity/state row, never unlimited shell text wrapping. At narrow width use two rows with status/alias first. Header summarizes typed arguments (command executable + short first argument; file path + range; task operation + target; participant target; context operation + revision); full exact args live in detail. Clip with explicit ellipsis; full ID/path accessible before choosing an effectful action. Card is read-only until an explicit action is invoked.

Default collapsed card shows tool name/call alias, purpose if actually supplied (not hallucinated), observed state, essential error, effect outcome and source availability. Successful/no-exception calls use compact summaries; refusals show resource/not_started; applied-but-result-failed says applied with result failure; timeout or retention uncertainty stays explicit. Unknown is not a red failure falsely implying safe rerun. Stream preview is labeled provisional; settled result is separate. Low-level process read/input/poll/control details nest under the high-level call/job rather than making peer assistant messages. Distinct concurrent calls must not share a single implicit current-tool stream.

Projection families: command/log (bounded safe text head/tail and exit/capture state), file/source (path, selected extent, snapshot, bounded excerpt), native structured result (named fields/tree, known/unknown totals), mutation/control (target/admission/result/effect), provider/participant (attempt/run/disposition and selected answer), fallback unknown tool (name/type, bounded safe text, full source link). Lua `display`/print stays explicitly authored display, not silently reclassified as model prose or tool execution. Existing command header+first3+last3 fold is preserved as a supported command preview, but header wrapping is bounded and essential outcome rendered outside omitted body.

Keyboard: Tab cycles native focus regions including transcript selection; arrows select keyed cards, Enter toggles bounded preview, `i` opens selected original, Ctrl-O opens selected call detail when a call is selected and the existing command catalog otherwise. Pointer click selects/toggles; Original control opens detail. In text-edit focus these letters remain text; focus label and context help state binding. Expand loads only a finite window and offers Original for more; no unbounded expand-all. Cards retained only in bounded display may retire: a tombstone/reference or deliberate source lookup opens retained detail if known, otherwise explicitly unavailable.

Inspector initially targets exact call/attempt/source, not latest command. Tabs/sections: Summary, Args, Result, Stream/original, Cause. Bounded page reads run on existing engine/adapter owner, never journal scans in input/paint. If retained-source admission unavailable/busy, keep prior page stale with selector/source/revision; page errors don't erase successful effects. List paging and byte paging have separate visible controls. `Ctrl-G`/Return goes to saved route/focus/anchor/draft; active ESC stops main turn without closing inspector.

Extent labels distinguish received, retained, selected, displayed and omitted bytes; unknown extents are unknown. Caught-up is not sealed. Child reaped is not stream EOF. Sealed incomplete capture stays incomplete. Retired resident job: control unavailable, retained output_ref still inspectable. Partial/corrupt/missing originals show exact known ranges/gaps and cause; no “full output” promise for bytes never retained. Call-linked semantic result originals need a proposed native locator adapter (OWNERS), not a fabricated output_ref for every tool. Inspection never executes the old tool or reads today's disk in place of the retained snapshot.

Safe rendering maps exact bytes to escaped display with byte/cell provenance; raw OSC/CSI, NUL and bidi controls cannot execute. Text selection maps to original ranges, never header decorations. Ordinary Copy defaults to safe visible text, explicitly labeled; **Export exact bytes** writes a deliberately selected range through an explicit file/export action with usual file-effect semantics, or displays hex. Exact unsafe bytes are never silently injected into terminal clipboard/paste. Clipboard support is capability-dependent; no automatic OSC52 from tool data. Binary/split UTF-8 has hex+offset view. Display truncation does not mutate originals or raw instrumentation.

## C5 — Continuous reading, live output and layout (R6, R9)

Follow live is explicit. PgUp/wheel/selection suspends following; Return live is a named action/button (End only in transcript focus), not an implied send. New output badge counts known new cards/updates, not fabricated unseen bytes. In reading mode freeze selected preview/page content and anchor by stable block/source identity + byte/line position + cell offset, not row count. New output can update overview badges without replacing the pinned text. Explicit Refresh shows a new selected source revision. Follow mode can update tail; completion does not switch preview orientation under a reader.

Fold/unfold above anchor, late insertion, resize and reflow preserve surviving source position; exact top cell may move with changed width. If display trimming removes anchor, keep an explicit `Display history retired · inspect retained source` marker and nearest surviving predecessor/successor deterministically; don't jump silently to live. Selection endpoints name original ranges, survive reflow where source exists, and show loss if unavailable. Inspect/return has a stack of route, selection, reader anchor, draft/cursor; background changes don't overwrite it. No history cloning per frame.

Layout priority: current input owner + main state/stop, draft, latest receipt/held queue, selected evidence + principal action, conversation, optional tasks/avatar/metadata. Hide empty task pane; collapse side details before identity/state. Dense mode reduces spacing, not semantic distinctions. At ~42x16 use stacked selected detail route with Back; one-line footer pages effective help rather than clipping it. Extremely tiny geometry uses native minimal shell: draft retained, stop/return input service intact, concise resize hint; no claim all detail readable at1x1. Wide view can show adjacent inspector without mandatory fixed sidebars.

Maintain owned nonblocking partial-write packet/baseline semantics across resize. Supersede obsolete unstarted presentation only; never half escape suffixes, accepted actions, discrete controls, originals or emitted raw metrics. Native input/control/draft/reading remain serviceable when Lua composition stalls. A blocked terminal cannot show feedback; tests must distinguish native control progress before drain from coherent eventual physical screen.

## C6 — Current state and actionable cause (R3, R7)

Strip says `Main t12 · worker active · last observed phase …`, `provider q/a retry wait`, `waiting for effort answer`, or `stop requested`. Only owner-supported phases appear; Lua computing with no new callback is `worker active; phase unavailable`, not endlessly Starting and not measured progress. Elapsed time is elapsed, not percent. Static active mark works without motion. Main completion leaves `children 1 / participants 2` if current scoped observation supports it; stale/partial counts include coverage and cannot turn unavailable into zero. Task declared active is not native progress.

Historical transcript retains timestamps/turn identity and labels snapshots as historical. Current shelf/strip read native current projections. Main turn, tool call, command job and participant each retain their hierarchy and independently terminal state. Waiting participant means available for direction, not finished or necessarily waiting for human. One error may need attention without stealing focus or forcing the human to monitor every call.

Failure detail joins actual error to turn/call/attempt/source. Show cause text/code, operation and known effect outcome when available; expose Cause link and bounded source. Distinguish cause linked, retained but unlinked, unavailable, retention failed. Where actual cause availability is unverified, say unavailable to this view, not “we know the Lua error”. Submitted source `error("x")` is not the exception record. `external_unknown(0)` alone never proves an external effect occurred or failed. Actions: Inspect result, Cause/source, Copy safe diagnostic, return to draft. No default Retry button after unknown effects. Deliberate new attempt remains ordinary authorized agency with a fresh identity and prior-unknown link, subject to existing admission fences, not a new approval dialog.

## C7 — Return to delegated work and direct (R3, R8, R10)

Ctrl-X/center offers current-session participant collection with scope, loaded pages, stale status; select exact run, read latest answer/result with full/ranged original link. Task label/owner is declared association only. Native run states, cancel_requested and remote disposition remain separate. `waiting · direction open` is distinct from sealed/draining/completed. Returning operator can understand result and outstanding direction without reading every low-level event.

Direction editor pins run_id and fresh message_id plus sender; preserves main draft. Submit is `Send direction at next request boundary`, not main Enter/steer. Owner receipt accepted/duplicate/conflict/full/sealed is explicit. Show later included delivery/result only from actual participant publication; otherwise `accepted; inclusion not observed`. Exact duplicate identity+arguments can reconcile while resident owner supports it; conflicting reuse refuses. Missing acknowledgment after possible admission stays unknown; no automatic new message. Await observes without sealing; Join seals and drains accepted directions, with exact target summary; stop requests cancellation separately. No UI action silently joins every run or claims remote stop. Closed/retired run preserves retained answer if source known; cannot inherit another row's target. Back returns main anchor/draft. These whole-task controls are proposed adapters over present Participants, not a new scheduler or tool-using remote team claim.

## C8 — Author, stage, activate and continue (R8, R10)

Instrument detail distinguishes: saved workflow path/model/effort settings (SessionStore); retained effective program/module/workflow/tool revisions; staged proposal and boundary; actual turn-pinned generation/source; running executable identity versus selected managed generation. `/session` is not proof a file's edits governed the current turn. File save, path selection and program_config activation have distinct receipts.

Open definition source/diff, edit native buffer, submit complete guarded proposal preserving unrelated fields. Syntax/base/refusal keeps edit and last effective definition. Model/Lua program_config and tool_define remain normal autonomous operations. During active work: show pending revision, current generation unchanged, eligible successful boundary; failure/interruption cancels staged activation. Busy `/workflow FILE` is a queued settings command, not a staged definition until actually dispatched. Observe effective revision and next turn's retained source separately. No general atomic interrupt-and-apply-now button: owner doesn't deliver it. Stop then edit are two operations with independent outcomes, not an atomic promise. Presentation-only theme/layout uses local boundary, not governing runtime activation. Failed Lua composition leaves last-good native shell/controls; reload requires real VM quiescence. No detaching live VM and calling it recovered.

## C9 — Omission, original, repair, resume/reopen (R5, R10)

Context-change notice is compact, with before/after revision and pending/applied/canceled status, ancestry/original link and actual request relation where available. No mandatory human acknowledgment of autonomous transforms. Operator notices a missing fact: open context detail, inspect changed entries/summary and bounded retained original by stable entry/source ID; restore original or author guarded corrected presentation preserving complete tool groups/live instructions. Content judgment remains human/model work, not structural validation.

Managed proposal during workflow stages; eligible successful boundary publishes. Direct operator outside workflow may publish immediately. Conflict preserves proposed repair text; explicit rebase observes current base, never silent overwrite. Unavailable original stays missing; no rerun old effect. Protocol repair is separately named `unanswered-call linkage repair`, only explicit recovery with start-unanswered set/no live children and current base; inserts unknown placeholders, never settles effects or repairs factual summary content. Physical audit capacity is separate; compaction does not reclaim it. Existing explicit successor/recovery instructions apply; no new continuity dependency.

Reopen starts with a continuity summary: saved draft recovered, queued items recovered requiring Send, last turn outcome/unknowns, retained history link and no inherited live custody. Show saved/effective settings and running generation in expandable Session detail; missing build-source manifest remains unknown, never guessed from a path. Ordinary reopen consumes no restart continuation intent; explicit resume-continue retains one-time semantics/fences. Unresolved local effects can block reopen/new effects under current contracts; summary cannot bypass them. Read-only originals/fresh independent session paths are offered only where actually supported. No recovery flags auto-selected, old PID adopted or effect replayed. Return to diagnostic task with preserved draft/references, not a claim that every pixel/stack survived.

## Progressive discovery and access

Footer shows input owner, effective Send/newline, ESC scope and Back/Original where relevant. `/help` gives task recipes; `/keys` explains current scope, capability and conflict resolution. Searchable local actions use actual availability; unsupported actions say why, not fake enabled buttons. Focus is visible via text/shape, selection separate from focus/activity. Tab navigation and full-width detail offer non-mouse paths. High-contrast/light/dark, ASCII/fallback glyphs, no-graphics and reduced/static motion preserve labels. Linear transcript/export and plain control routes are useful alternatives, not screen-reader qualification. Physical keyboard, complex grapheme/IME, contrast and assistive-technology task observations remain explicit later work; no accessibility conformance claim.
