## Selected model: a conversation with receipts and linked evidence

Keep chat the principal working surface, not a dashboard requiring continuous supervision. Three persistent instruments form one system:

1. **Intention receipts:** each deliberate Send produces one stable local referent with source text and an honest current badge. The current queue sits immediately above the composer. A compact receipt remains visible through delayed launch; the transcript does not manufacture a second YOU message on launch.
2. **A current-work strip:** main turn state and input owner, with exceptions/remaining children/participants linked, separate from historical transcript statements. Escape stops the active main turn in harness-controlled modes, rather than dismissing one invisible layer at a time. Local Back and explicit PTY return have other controls.
3. **Call-linked evidence:** compact typed tool cards, expandable preview and a selected-original inspector over retained sources. Reading is anchored and distinct from Follow live. Details never rerun effects, and authored views reuse these references rather than invent execution state.

The model addresses one episode: compose → establish receipt → correct pending intentions → work/read/interrupt → inspect a consequential result → resume/delegate/change instruments → leave and return. It is not three patches for Escape, a spinner and formatting.

## Rationale and alternatives

The [accepted reference synthesis](../chat-usability-2026-10-27/REFERENCES.md) supplies mechanisms, not brands to copy. Instrumental interaction separates composer reaction from object response: emptying the editor is not a send acknowledgment. Direct manipulation's semantic/articulatory distance explains why raw data somewhere in chat does not answer “already sent?” or “which error?”. Pi's local expansion motivates call locality but its flooding cost argues for bounded previews plus originals. Codex's pending identity motivates local receipts; content matching does not justify deduplication. Crush's moving tail motivates stable reader snapshots rather than switching preview orientation on completion. libvaxis shows why another thread is not a guarantee when queues block.

This applies [interaction theory](../../docs/INTERACTION_THEORY.md) and [doctrine](../../docs/TUI_DOCTRINE.md) to task relationships. Keep generative agency: model, human and Lua operate the same real owners without screen manipulation or ordinary approval ceremony. Craft uses calm spacing, one readable argument line, explicit roles and restrained semantic accents; optional animation is activity, never progress evidence.

- Dismiss-first ESC protects local habits but recreates unusable stop under palettes/inspectors. Stop-first costs a new local Back habit: preserve edits/selections, expose the rule, retain Ctrl-C fallback, test conflicts.
- Full inline output saves activation but floods conversation. Inspector-only tools hide relationships. Use compact cards + bounded expansion + direct original detail; one source, not two stores.
- Queue as count alone leaves the particular intention invisible; full queue transcript is noisy. Use a current shelf with selected detail and persistent receipt identity; long queues page.
- Every main send as steer would be attractive but false. Keep next-turn queue; participant direction is explicitly addressed. Main live steering remains unsupported.
- Requiring parked composition first is rejected. Extend current native seams and delivered isolated Lua bridge where useful, with no S3a/S3b dependency or sibling merge.
