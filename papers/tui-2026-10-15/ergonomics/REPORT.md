# Dense terminal workspaces and operator control: source reconnaissance

2026-10-15. Supplement for the **Blackbird repository**. This lane acquired and inspected nine terminal applications and seven primary papers. It covers information structure, stable navigation, action discovery, control feedback and how expensive work reaches the screen. Rendering frameworks, C++/Lua embedding, MIDI and haptics have separate research owners. Here TUI means textual terminal interface; papers using TUI for *tangible* interfaces belong to a different search branch.

The strongest recurring mechanism is preserving a useful relationship between the operator's current target, the visible context, and work arriving asynchronously. A beautiful high-refresh screen can still move the target, replace the help being read, block cancellation behind background work, or show an apparently complete result that was actually truncated. Source inspection found unusually concrete examples of each design pressure. It establishes mechanisms and questions; no application in this corpus has been benchmarked here, and no implementation is selected for adoption.

See [MANIFEST.md](MANIFEST.md), [sources.tsv](sources.tsv), [literature.tsv](literature.tsv) and [SHOPPING_LIST.md](SHOPPING_LIST.md). Immutable source ZIPs total **54,240,979 bytes**; sanitized extracts retain **12,203 files / 105,009,736 bytes**. All nine source acquisitions and seven PDF acquisitions succeeded. Reference programs and their tests were not executed.

## What the applications teach

### lnav: preserve the place while building the interpretation

The source offers a particularly useful combination of dense log navigation and explicit work budgeting. Its loop assigns an interactive deadline of 50ms, starts rescans asynchronously, shortens the deadline to 10ms on an interactive rescan, and passes deadlines into index rebuilding. Statement mapping advances in slices bounded by the earlier of the loop deadline and a further 20ms. These are implementation parameters, not observed latency guarantees. An individual operation can still exceed a deadline unless its inner work cooperates. [Loop and work slicing](https://github.com/tstack/lnav/blob/753b61bf9c4987342a3f23000ed2a466187d4429/src/lnav.cc#L2026).

More interesting ergonomically: the loop skips index rebuilding while text is selected. That preserves the material a human is acting on while new material arrives. The UI supports semantic breadcrumbs, marked search/error locations in the scrollbar, and synchronization of time positions between log and histogram views. These mechanisms connect dense summaries to exact evidence without requiring another search from scratch. [Selection protection](https://github.com/tstack/lnav/blob/753b61bf9c4987342a3f23000ed2a466187d4429/src/lnav.cc#L2154), [navigation documentation](https://github.com/tstack/lnav/blob/753b61bf9c4987342a3f23000ed2a466187d4429/docs/source/ui.rst#L19).

Blackbird experiment: inspect an old tool result while a burst of concurrent output arrives; copy a span, move through a causal summary, then return to the exact span. Record target movement, lost selection, wrong-copy incidents and time to recover the original place.

### btop: a worker thread does not make the control path independent

btop collects and draws through a secondary runner while the main loop polls input and schedules updates. The implementation is worth studying for dense linked resource panels, detailed process inspection and following a selected process by PID. The operator's target has identity beyond a row position. [Main loop](https://github.com/aristocratos/btop/blob/119c8d83e1331ac6fbc9aef0fe78c7fadda9b391/src/btop.cpp#L1136), [process follow/detail](https://github.com/aristocratos/btop/blob/119c8d83e1331ac6fbc9aef0fe78c7fadda9b391/src/btop_input.cpp#L360).

There is also a clear counterexample to architectural slogans: `Runner::run` first waits as much as 10 seconds plus another 20 seconds for an active runner, and `Runner::stop` can wait 30 seconds. These are concrete paths that can delay the caller when the runner stalls. This finding does **not** establish that ordinary use freezes, nor identify why any runner would stall. It establishes that moving work to another thread alone does not prove control responsiveness. [Runner waits and failure handling](https://github.com/aristocratos/btop/blob/119c8d83e1331ac6fbc9aef0fe78c7fadda9b391/src/btop.cpp#L731).

Blackbird experiment: stall the collector, renderer, terminal sink and subprocess independently. Ask which component reads the interrupt, publishes acknowledgment, applies cancellation and displays completion. Keep request acknowledgment separate from actual work termination.

### bottom: separate collection and input, then inspect the common consumer

bottom has a dedicated input thread polling at 20ms, a collector thread and a central event receiver. Collector sleeps support cancellation. The central consumer handles keys, data updates and drawing; data conversion and drawing therefore remain work ahead of later input in that consumer. A channel boundary is useful separation, but does not by itself establish queue fairness or bounded input-to-paint delay. [Input and collection](https://github.com/ClementTsang/bottom/blob/7d65d62c8310f592727e6a142007f761504c2c8b/src/lib.rs#L145), [consumer](https://github.com/ClementTsang/bottom/blob/7d65d62c8310f592727e6a142007f761504c2c8b/src/lib.rs#L395).

Its density controls include freezing new displayed data, expanding one widget, and a basic mode that removes graphs. These are different useful reductions: preserve a reading position; allocate space to the chosen object; change which representation consumes space. Basic mode explicitly disables expansion/custom layout. [General controls](https://github.com/ClementTsang/bottom/blob/7d65d62c8310f592727e6a142007f761504c2c8b/docs/content/usage/general-usage.md#L19), [basic mode](https://github.com/ClementTsang/bottom/blob/7d65d62c8310f592727e6a142007f761504c2c8b/docs/content/usage/basic-mode.md#L1).

Blackbird experiment: compare one dense multi-activity view, temporary focus expansion, and a text-first compact view on the same diagnosis. Measure successful identification and control of the relevant activity, not visible character count.

### Yazi: action descriptions, partial rendering and explicit UI layers

Yazi's default keymap stores keys, action sequences and descriptions together, including prefix sequences, direct actions and changes to metadata shown per file. Its which-key component displays candidate continuations in configurable columns and declines to draw when there is insufficient space. The executor dispatches actions by layer, including manager, tasks, input, help and which-key. This is a rich reference for making a large command vocabulary accessible without showing every control continuously. [Keymap](https://github.com/sxyazi/yazi/blob/ffb2e78cc70341946c04befa52e14a4494015ce8/yazi-config/preset/keymap-default.toml#L1), [continuation display](https://github.com/sxyazi/yazi/blob/ffb2e78cc70341946c04befa52e14a4494015ce8/yazi-fm/src/which/which.rs#L21), [layered dispatch](https://github.com/sxyazi/yazi/blob/ffb2e78cc70341946c04befa52e14a4494015ce8/yazi-fm/src/executor.rs#L18).

The application schedules renders with 10ms spacing, drains pending events, and distinguishes partial, normal and forced renders. Partial rendering targets progress and notifications. Continuous event drainage and synchronous dispatch deserve measurement under floods; the existence of a render interval is not an end-to-end deadline. [Event/render scheduling](https://github.com/sxyazi/yazi/blob/ffb2e78cc70341946c04befa52e14a4494015ce8/yazi-fm/src/app/app.rs#L32), [partial rendering](https://github.com/sxyazi/yazi/blob/ffb2e78cc70341946c04befa52e14a4494015ce8/yazi-fm/src/app/render.rs#L19).

Blackbird experiment: expose one action through a key chord, command search, Lua and an external controller; compare target selection, visible command name and resulting effect. The device adapters can differ while the operation remains identifiable and inspectable.

### Helix: discoverable command grammar, priority and a deliberate render wait

Helix's keymap implements a trie with pending keys, command sequences, sticky prefixes and cancellation. The reverse map reconstructs keys for commands. Its documented selections, minor modes and jumplist provide compact navigation grammar plus a way back. This is a useful reference for expressive controls whose current parse state can be displayed. Its source also explicitly restricts macro bindings inside command sequences; the feature envelope must be read rather than inferred from configurability. [Trie and reverse map](https://github.com/helix-editor/helix/blob/ba40e547426b0f9896c8bdc699a4ab11f2b37dbc/helix-term/src/keymap.rs#L185), [documented navigation](https://github.com/helix-editor/helix/blob/ba40e547426b0f9896c8bdc699a4ab11f2b37dbc/book/src/keymap.md#L33).

The application uses a biased async select with signals and terminal input before job callbacks and editor events. Selection priority applies while selecting; it cannot preempt an already-running handler. A second mechanism intentionally delays drawing: `start_frame` acquires an exclusive lock and waits for read guards held by asynchronous computations. That trades frame consistency against waiting time. [Event priority](https://github.com/helix-editor/helix/blob/ba40e547426b0f9896c8bdc699a4ab11f2b37dbc/helix-term/src/application.rs#L306), [render lock](https://github.com/helix-editor/helix/blob/ba40e547426b0f9896c8bdc699a4ab11f2b37dbc/helix-event/src/redraw.rs#L12), [frame entry](https://github.com/helix-editor/helix/blob/ba40e547426b0f9896c8bdc699a4ab11f2b37dbc/helix-term/src/application.rs#L261).

Blackbird experiment: show pending prefix and command meaning, then inject asynchronous results and a slow presentation computation. Does input still receive feedback? Can a busy collaborator prevent the UI from drawing a cancellation acknowledgment?

### Kakoune: expose the operand and keep control state legible

Kakoune makes oriented selections central, with multiple selection operations, counts and explicit manipulations of the target before editing. The input handler displays selection counts, hidden selections, register/parameter state and command information. The lesson for an agent workspace is an inspectable target: which messages, tasks, participants, outputs or context spans will an action affect? Editing grammar does not transfer automatically to all orchestration, but visible target state is directly relevant. [Selection model](https://github.com/mawww/kakoune/blob/4d4ee86c2d039c2a5f29f109e7e59105d2073046/README.asciidoc#L367), [mode information](https://github.com/mawww/kakoune/blob/4d4ee86c2d039c2a5f29f109e7e59105d2073046/src/input_handler.cc#L362).

The event manager uses file-descriptor watchers and timers with normal/urgent event modes. Urgent mode excludes normal watchers, and an explicit urgent-event call performs a zero-timeout pass. This is source evidence for a control-service mechanism, not proof that every long operation yields to it. [Event manager](https://github.com/mawww/kakoune/blob/4d4ee86c2d039c2a5f29f109e7e59105d2073046/src/event_manager.cc#L76).

Blackbird experiment: form a multi-object selection, change view, receive new objects and invoke a batch control. Require the operator to predict the targets before dispatch; compare the prediction with the actual selected identities. Include hidden selected objects and a model editing the same collection.

### fzf: independently progressing preview work and composable interaction

fzf separates preview subprocess output reading, periodic preview rendering and cancellation into distinct goroutines. A new preview request cancels the prior preview, while result versions inform preview state changes. The renderer distinguishes delayed preview and partial output. This shows how discovery can remain useful before a slow preview finishes, with explicit replacement and termination paths to study. It does not prove that an adversarial child or slow terminal cannot obstruct any path. [Preview lifecycle](https://github.com/junegunn/fzf/blob/c8c2d0828a94a00879ceb6f95112a42e3ea322cf/src/terminal.go#L6407), [result consumption](https://github.com/junegunn/fzf/blob/c8c2d0828a94a00879ceb6f95112a42e3ea322cf/src/terminal.go#L6740).

The larger file also exposes actions that change preview, execute commands, transform bindings and coordinate asynchronous updates. This flexibility deserves attention alongside complexity: not every action shares the same progress semantics, and some wait/track modes explicitly allow only cancellation and selected controls. [Restricted-mode dispatch](https://github.com/junegunn/fzf/blob/c8c2d0828a94a00879ceb6f95112a42e3ea322cf/src/terminal.go#L7091).

Blackbird experiment: rapidly change the focused task while previews arrive out of order; then stop a preview that floods output or ignores ordinary termination. Observe focus stability, stale preview exposure, input acknowledgment and eventual child cleanup separately.

### tig: linked evidence views and incremental child output

tig offers a compact implementation reference for moving between repository summary, commit, diff and staging detail. The update path checks child-pipe readiness without blocking, reads available lines, restores view position and redraws dirty regions. The input loop updates views before reading input, adjusting its wait while loading. This is an explicit incremental work path; cost per available batch and terminal output still matter. [View updates](https://github.com/jonas/tig/blob/5a8fd507cd7e866833fa029fa7c7c098736a72c2/src/view.c#L622), [input loop](https://github.com/jonas/tig/blob/5a8fd507cd7e866833fa029fa7c7c098736a72c2/src/display.c#L790), [pipe readiness](https://github.com/jonas/tig/blob/5a8fd507cd7e866833fa029fa7c7c098736a72c2/src/io.c#L503).

Blackbird experiment: navigate from task summary to exact change/output, follow a related participant and return. Keep the same object selected while the collection grows. Test this with a large history and simultaneous command output; determine how much of the available batch the UI processes before servicing control.

### Harlequin: help that remains readable after taking focus

Harlequin's key panel is a precise small example of attention-aware presentation. Its binding table caches the displayed keys while the help list has focus; otherwise focusing help would replace the very keys being consulted with the help widget's own bindings. Its palette also reports the binding attached to a command. This solves a concrete instability between discoverability and focus. [Focused help preservation](https://github.com/tconbeer/harlequin/blob/33f63fdfa12c0d6b69279f621de72e3a797a570a/src/harlequin/components/keys_panel.py#L9), [palette](https://github.com/tconbeer/harlequin/blob/33f63fdfa12c0d6b69279f621de72e3a797a570a/src/harlequin/app.py#L1181).

Query execution, fetching and cancellation use thread workers; cancellation has its own worker group and depends on adapter support. Fetching distinguishes a hard query limit from a softer display cap and detects overflow so a partial table does not claim completeness. A comment explicitly bounds a timezone wait because blocked fetch workers share the pool used by cancellation. Logical worker groups are therefore not necessarily reserved cancellation capacity. [Execute/cancel](https://github.com/tconbeer/harlequin/blob/33f63fdfa12c0d6b69279f621de72e3a797a570a/src/harlequin/app.py#L1635), [fetch and shared-pool wait](https://github.com/tconbeer/harlequin/blob/33f63fdfa12c0d6b69279f621de72e3a797a570a/src/harlequin/app.py#L1820).

Blackbird experiment: fill ordinary worker capacity with slow work, then invoke stop, inspect and help. Present incomplete results with an explicit indication that more material exists. Preserve the action vocabulary being read while help itself acquires focus.

## Primary literature seed for the next pass

These are initial readings for a later UX/HCI/BHI investigation, not a completed literature synthesis. The first six PDFs have been inspected for the ideas below; the distributed cognition paper was inspected visually on printed pages 174–176 because the acquired copy is a scan. SWE-agent was read for its interface principles and ablations. Detailed methods/results across the entire corpus remain next-pass work.

| Work | What it contributes | Limits on transfer |
| --- | --- | --- |
| [Shneiderman, 1996: The Eyes Have It](https://www.cs.umd.edu/users/ben/papers/Shneiderman1996eyes.pdf) | Seven task categories include relating, history and extraction as well as overview, zoom, filtering and detail. Dense work needs navigable relationships and return paths, not merely small typography. | Taxonomy and design examples; no terminal-agent optimum or universal information-density number. |
| [Amershi et al., 2019: Guidelines for Human-AI Interaction](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf) | Invocation, dismissal, correction, contextual relevance, cautious adaptation and global controls provide useful questions for steering an active agent. | Validation concerns guideline applicability/clarity across AI products, not measured performance of a coding harness. |
| [Horvitz, 1999: Principles of Mixed-Initiative User Interfaces](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf) | Automated services and direct manipulation can coexist; attention, timing, termination, uncertainty and the cost of poor guesses matter. | Historical scheduling application; no warrant to insert routine approval dialogs into the operator's explicitly authorized workflow. |
| [Mark, Gudith and Klocke, 2008: The Cost of Interrupted Work](https://www.ics.uci.edu/~gmark/chi08-mark.pdf) | The experiment found faster completion under interruption alongside greater reported stress, frustration, time pressure and effort. | A narrow task study; faster completion alone does not establish better ergonomics. Do not turn it into a universal recovery-time statistic. |
| [Hollan, Hutchins and Kirsh, 2000: Distributed Cognition](https://interactivity.ucsd.edu/articles/DCog/DCog.pdf) | The unit of analysis can include people, external representations and coordination over time. For Blackbird, inspect the human/model/tool/history system together. | The framework does not establish that a language model has human cognitive mechanisms. Opening pages read; remaining examples await the deep pass. |
| [MacKenzie and Ware, 1993: Lag as a Determinant of Human Performance](https://www.yorku.ca/mack/p488-mackenzie.pdf) | Target acquisition under imposed lag demonstrates that delayed feedback affects action performance and errors, not just subjective annoyance. | Pointing task with historical hardware. It supplies motivation for closed-loop measurement, not a numeric keyboard/MIDI latency budget. |
| [Yang et al., 2024 v3: SWE-agent](https://arxiv.org/abs/2405.15793v3) | Agent action/observation design is an independent axis. Section 5.1 shows an iterative search interface encouraging exhaustive next-result loops; its performance there was worse than the no-search variant. Compact actions and feedback deserve experiments. | Those models, tasks, budgets and ablations do not select today's command vocabulary or output caps. Test with Blackbird's current models and retained originals. |

BHI can use the established ACI vocabulary to find relevant prior work while retaining the operator's broader meaning. A model's control interface includes operation names, target identities, batch composition, failures, references to retained evidence, cancellation, resumability and feedback about ongoing work. A beautiful human screen is not evidence that these are usable by a model; compact machine output is not evidence that the human can understand and steer the same work.

## Questions and discriminating experiments for the UX/HCI/BHI pivot

1. **What must remain instantly operable?** Trace keyboard/device arrival → decode → action admission → acknowledgment → state change → paint. Interrupt acceptance, actual termination and displayed termination are different events. Use a known input sequence and injected stalls in one subsystem at a time. Include output backpressure and a full worker pool. Avoid extrapolating from idle frame rate.
2. **How is the operator's target preserved?** Compare identity-based focus with row-based focus while tasks reorder, output arrives and filters change. Exercise multi-selection across views, hidden targets, copy selection and model edits. Count wrong-target actions and recovery work.
3. **What does density buy on a real task?** Compare dense overview, focused detail and linked views at ordinary and narrow terminal sizes. Ask the operator to find a blocked participant, locate the exact failed effect, steer it and return to the previous task. Measure correctness, time, unnecessary view changes and subjective effort. Character occupancy alone cannot answer this.
4. **How does an expert learn an unfamiliar command family?** Compare searchable commands, prefix continuations, context help and a persistent control legend using the same action vocabulary. Add custom mappings, device actions and a keyboard layout change. Check whether help names the actual active binding and remains readable when focused.
5. **When should activity attract attention?** Compare streaming every update, coalesced background status and explicit escalation for blocked/failed work. Let the operator work on another result. Observe missed relevant transitions, interruptions, time pressure and resumption errors. Preserve all raw events outside the display; presentation reduction need not discard originals.
6. **Can human and model refer to the same thing?** Give each the same diagnosis/control task through its own interface. Require selection of the same task/operation/output identity, acquisition of a bounded view of originals, and interpretation of pending/success/failure/unknown state. Compare extra round trips, mistaken identities, recoverable errors and work accomplished.
7. **Does expression compose?** Perform one useful operation through keyboard, Lua and a future controller adapter. Compose it with selection, filtering, repeat and cancellation. A device event need not masquerade as text input to share an operation, but the operation's target/effect must stay intelligible. Input-system research owns the concrete transport/design.
8. **Can appearance stay exact under change?** Exercise resize during a prefix, notification during help, background completion while editing, grapheme/wide-character selection, long paths and incomplete previews. The oracle is the operator's intended target and visible action state. Current Blackbird behavior must be checked at its present revision before filing defects; earlier renderer critiques may be stale.

Suggested next reading order: lnav's view navigation and work slicing; Harlequin's focused-help and result-limit behavior; fzf's preview lifecycle; Helix/Kakoune's command state and event handling; then the papers' methods and agent-interface ablations. These comparisons can sharpen the problem statement before choosing controls or writing the implementation plan.
