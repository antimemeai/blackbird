# Direct command-inspector adoption oracle

This lane owns permanent behavior assertions for root's local adapter, not its
implementation or another product review. Real CommandJobs workers supply exact
retained bytes and stable command IDs. Scene properties and rendered cells must
show those actual observations while command launches, received/retained
frontiers, terminal settlement and domain controls remain unchanged by inspector
navigation. Escape/control data must be presented literally/safely, never emitted
as terminal instructions. The observation owner has its own allocation/budget
oracle; this adapter fixture attacks adoption and provenance.

Cases: `semantic` runs real private workers and verifies selected identity,
literal presentation and unchanged frontiers/launch counts; `raw` runs the same
owner with genuine RawRuntime capture, then independently decodes4087 and actual
native read records to reconstruct selected output from recorded source ranges;
`pressure` exhausts a standalone producer's actual physical CONTROL grants and
requires exact old Scene snapshot/applied reference plus an explicit stale
notice, with no capture failure marker; `runtime-pressure` combines actual worker
sources, a previous successful adoption, real grant exhaustion and unrelated
command controls before recovery. Try refusal emits no apply and cannot publish
new properties. A released grant allows later refresh without domain replay.

Decode the documented native wire directly, including owner/incarnation,
origin reference, generation, adopted/has-error and optional error fields.
No production encoder/parser constructs expected records. For each adopted
window, resolve every actual source reference to native2008 read payload bytes,
check logical chunk+offset continuity and exact coverage, and compare reconstructed
bytes to the worker's known payload and accepted selected-scene presentation.
Check generation monotonicity and distinguish successful apply from rejected
observation. The root owns CMake/build coordination and one independent concrete
code challenge after green; generic components must first finish their own red
phase. No source product edit, broad suite, real provider/session, artwork or AFL
operation occurs here.

The existing actual-main command custody PTY fixture also needs its discovery
oracle moved from `/jobs` JSON to an explicitly requested native process read:
`/jobs` now intentionally opens the inspector. Its private child still writes
the actual PID. A deliberate `/lua` call reads the real registry, requires
exactly one matching PID and prints that row's canonical job ID plus PID in a
fresh marker. The echoed code has no literal matching job ID. Python accepts
exactly one marker for that actual PID, preserving every subsequent foreground,
input/resize/signal, task separation, launch-count and cleanup assertion.
This is an explicit engine operation rather than a UI paint-time registry read.
