## Q1. What exactly does each mechanism remove or replace, when, and with what text? What stays verbatim?

### Takeaway
SWE-agent's classic mechanism is `LastNObservations`. It runs on every query, without state, over an untouched raw history. It replaces the content of every observation except the first (the problem statement / instance template) and the last *n*, using the text `Old environment output: (N lines omitted)`. Actions and thoughts stay verbatim.

OpenHands works on an append-only event log and has two families of condenser:
1. Stateless per-step maskers: `<MASKED>`, and `Visited URL … Content omitted` for browser output.
2. "Rolling" condensers that write a durable `CondensationAction`/`Condensation` event. That event forgets a contiguous middle range and may insert an LLM summary after a kept prefix.

V1 keeps only the LLM-summarizing rolling condenser. Its forgetting range snaps to boundaries that never split a tool call from its result, a parallel tool-call batch, or a thinking tool loop.

### Cited Findings

**SWE-agent: history processors (`sweagent/agent/history_processors.py`)**
- History processors run in a chain inside the `messages` property, each time the model is queried. They act on `self.history` filtered to the current agent. The stored history is not rewritten ([SWE agents.py:539-553](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L539-L553)). The `.traj` file saves the full `history` along with `trajectory` ([agents.py:762-775](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L762-L775)).
- `LastNObservations` docstring: "Elide all but the last n observations or remove tagged observations. This is our most classic history processor, used in the original paper to elide but the last 5 observations. Elided observations are replaced by "Old environment output: (n lines omitted)"" ([history_processors.py:85-112](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L85-L112)).
- Selection works as follows ([history_processors.py:147-155](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L147-L155)):
  - Candidates are entries with `message_type == "observation"` that are not `is_demo`.
  - `last_removed_idx = max(0, (len(obs)//polling)*polling - n)`.
  - The elided set is `observation_indices[1:last_removed_idx]`, with the comment "We never remove the first observation, as it is the instance template".
- The instance template is itself recorded as an observation: `_add_templated_messages_to_history` gives every templated message `message_type: "observation"` ([agents.py:701-712](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L701-L712)), and `add_instance_template_to_history` uses it ([agents.py:750-760](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L750-L760)). The system prompt is `message_type: "system_prompt"` ([agents.py:613-614](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L613-L614)) and demonstrations are `is_demo`, so neither is ever elided.
- The exact replacement text is `f"Old environment output: ({num_text_lines} lines omitted)"`. When images were present it adds `f" ({num_images} images omitted)"`. Line and image counts come from `_get_content_stats` ([history_processors.py:23-28](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L23-L28), [:166-175](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L166-L175)). The entry is shallow-copied (`data = entry.copy()`) and only `content` is replaced.
- Tag overrides: `always_remove_output_for_tags = {"remove_output"}` elides an observation even inside the last *n*. `always_keep_output_for_tags = {"keep_output"}` keeps one outside the window ([history_processors.py:124-132](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L124-L132), [:161-165](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L161-L165)).
- `polling` (default 1) exists for prompt caching. The docstring says "we will now keep between `n` and `n+polling` observations" ([history_processors.py:117-122](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L117-L122)).
- `ClosedWindowHistoryProcessor` handles the old windowed file viewer. Walking backwards, it keeps the newest window per file, keyed by `[File: <path> (N lines total)]`. Older windows of the same file become `Outdated window with {len(matches)} lines omitted...\n`. Only `role == "user"`, non-demo entries are touched ([history_processors.py:215-258](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L215-L258)).
- `RemoveRegex` deletes regex matches, by default `["<diff>.*</diff>"]` with DOTALL, from every entry except the last `keep_last` (default 0). Nothing marks the deletion ([history_processors.py:305-337](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L305-L337)).
- Other processors: `CacheControlHistoryProcessor` only moves Anthropic `cache_control` marks to the last `last_n_messages` user/tool messages, default 2 ([history_processors.py:261-302](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L261-L302)). `ImageParsingHistoryProcessor` converts markdown base64 images into multimodal parts ([:340-387](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L340-L387)). `DefaultHistoryProcessor` is the identity ([:74-82](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L74-L82)).

**SWE-agent: truncation when the observation is recorded (permanent in history)**
- `max_observation_length` defaults to `100_000` characters ([agents.py:79-82](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L79-L82)). An over-length observation is rendered once, keeping the head only, as `Observation: {{observation[:max_observation_length]}}<response clipped><NOTE>Observations should not exceeded {{max_observation_length}} characters. {{elided_chars}} characters were elided. Please try a different command that produces less output or use head/tail/grep/redirect the output to a file. Do not use interactive pagers.</NOTE>` ([agents.py:69-77](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L69-L77), [:714-748](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L714-L748)).
- An empty observation uses `next_step_no_output_template` instead ([agents.py:730-732](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L730-L732)).
- `config/bash_only.yaml` overrides the limit to `10_000`. It keeps head and tail halves in `<observation_head>`, `<elided_chars>{{elided_chars}} characters elided</elided_chars>` and `<observation_tail>` blocks. Its warning tells the model to "redirect output to a file and then search in that file" ([bash_only.yaml:181-200](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/config/bash_only.yaml#L181-L200)).
- When a model output fails to parse, it is re-queried with a temporary history: `self.messages + [assistant output, user error]`. "If the model is able to correct itself, the records of the mistakes will not be part of the history (but they are saved in the trajectory)" ([agents.py:799-821](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L799-L821)). The default is `max_requeries: 3` ([agents.py:158](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/agents.py#L158)).

**OpenHands V0 (tag 1.6.0): event log, View and condensers (`openhands/memory/`)**
- `View.from_events` forgets every event listed in a `CondensationAction`, plus the action itself and any `CondensationRequestAction`. If the most recent `CondensationAction` that carries a summary has `summary`/`summary_offset`, it inserts `AgentCondensationObservation(content=summary)` at `summary_offset` ([OH0 memory/view.py:49-96](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/view.py#L49-L96)).
- A rolling condenser's `Condensation` is returned *as the agent's action* for that step. It lands in the event stream, and the next step's View applies it ([OH0 codeact_agent.py:207-213](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/agenthub/codeact_agent/codeact_agent.py#L207-L213); [condenser.py:169-193](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/condenser.py#L169-L193)).
- `ObservationMaskingCondenser` replaces every `Observation` whose *event* index satisfies `i < len(view) - attention_window` with `AgentCondensationObservation('<MASKED>')`. The window is counted in events, not observations. It is stateless: it runs every step and writes no event. The class default is `attention_window=5` ([observation_masking_condenser.py:11-28](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/observation_masking_condenser.py#L11-L28)).
- `BrowserOutputCondenser` keeps the last `attention_window` (default 1) `BrowserOutputObservation`s. It replaces older ones with `AgentCondensationObservation(f'Visited URL {event.url}\nContent omitted')`. Its docstring says screenshots and accessibility trees "consume a lot of tokens without any benefits in performance" ([browser_output_condenser.py:11-40](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/browser_output_condenser.py#L11-L40)).
- `RecentEventsCondenser` keeps `view[:keep_first] + view[-(max_events-len(head)):]` with class defaults `keep_first=1, max_events=10`. It leaves no placeholder and writes no event ([recent_events_condenser.py:8-22](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/recent_events_condenser.py#L8-L22)).
- `AmortizedForgettingCondenser` runs when `len(view) > max_size` or a request is unhandled. It keeps `keep_first` head events plus a tail, together sized to `max_size // 2`, and emits a `CondensationAction(forgotten_events_start_id=min, forgotten_events_end_id=max)` with no summary. Class defaults are `max_size=100, keep_first=0` ([amortized_forgetting_condenser.py:13-58](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/amortized_forgetting_condenser.py#L13-L58)).
- `LLMSummarizingCondenser` (V0) triggers on `len(view) > max_size` or a request ([llm_summarizing_condenser.py:160-161](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/llm_summarizing_condenser.py#L160-L161)). How it builds the summary ([llm_summarizing_condenser.py:52-158](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/llm_summarizing_condenser.py#L52-L158)):
  - It keeps `keep_first` head events and `max_size//2 - keep_first - 1` tail events.
  - If `view[keep_first]` is the previous summary, the prompt carries it as `<PREVIOUS SUMMARY>`.
  - Each forgotten non-summary event is added as `<EVENT id=…>str(event)</EVENT>`. Each event is middle-truncated to `max_event_length=10_000`.
  - The prompt asks for USER_CONTEXT, TASK_TRACKING, COMPLETED, PENDING, CURRENT_STATE, CODE_STATE, TESTS, CHANGES, DEPS and VERSION_CONTROL_STATUS.
  - The result is a `CondensationAction(... summary=summary, summary_offset=keep_first)`.
  - Prompt caching is turned off for the summarizer LLM ([:167-172](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/llm_summarizing_condenser.py#L167-L172)).
- `StructuredSummaryCondenser` uses the same windowing but forces a `create_state_summary` function call into a `StateSummary` pydantic model. If parsing fails it falls back to an empty `StateSummary()` with a warning. It requires function calling ([structured_summary_condenser.py:162-305](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/structured_summary_condenser.py#L162-L305)).
- `LLMAttentionCondenser` asks an LLM to rank event IDs by importance, using `response_format` JSON schema. It keeps the top `max_size//2 - keep_first` events, back-filling the most recent ones if too few come back, and forgets the rest by explicit ID list. Forgotten events need not be contiguous ([llm_attention_condenser.py:23-119](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/llm_attention_condenser.py#L23-L119)).
- `ConversationWindowCondenser` runs **only** on an explicit condensation request ([:176-177](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/conversation_window_condenser.py#L176-L177)). What it keeps and drops ([conversation_window_condenser.py:20-174](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/conversation_window_condenser.py#L20-L174)):
  - It keeps the system message, the first user message, and the recall action/observation for that message.
  - It keeps `max(1, non_essential // 2)` of the most recent events.
  - It drops observations dangling at the start of the kept slice.
  - It writes no summary.
- `CondenserPipeline` runs condensers in order and stops at the first `Condensation` ([pipeline.py:34-40](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/pipeline.py#L34-L40)).
- When the prompt is built, every observation is middle-truncated by `truncate_content` to `max_message_chars`. The default is `30_000` ([OH0 core/config/llm_config.py:75-77](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/core/config/llm_config.py#L75-L77)). The text is `content[:half] + '\n[... Observation truncated due to length ...]\n' + content[-half:]` ([OH0 events/serialization/event.py:167-178](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/events/serialization/event.py#L167-L178)).
- If the initial user message was condensed away, it is deliberately *not* re-inserted, "to prevent re-execution of old instructions" ([OH0 conversation_memory.py:838-870](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/conversation_memory.py#L838-L870)).

**OpenHands V1 (software-agent-sdk): single summarizing strategy**
- The condenser package holds only `LLMSummarizingCondenser`, `NoOpCondenser` and `PipelineCondenser` (`openhands-sdk/openhands/sdk/context/condenser/`). V1 has no observation-masking, browser-masking, recent-events or amortized condenser.
- README: "the context window is condensed by replacing the first half of all events with a single summary event". It describes "soft" triggers (resource limits; skip if a valid condensation is impossible) and "hard" ones (explicit requests or context errors; fall back to `hard_context_reset`) ([OH1 condenser/README.md:3-37](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/README.md)).
- Fields: `max_size=240`, `max_tokens=None`, `keep_first=2`, `minimum_progress=0.1`, `hard_context_reset_max_retries=5`, `hard_context_reset_context_scaling=0.8` ([llm_summarizing_condenser.py:63-87](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L63-L87)).
- Trigger reasons: REQUEST (an unhandled `CondensationRequest`), TOKENS (the view's token count exceeds `min(max_tokens, agent_llm.effective_max_input_tokens)`) and EVENTS (`len(view) > max_size`) ([:115-173](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L115-L173)). TOKENS and REQUEST are HARD; EVENTS-only is SOFT ([:175-203](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L175-L203)).
- How much tail is kept depends on the reason, and the strictest wins ([:278-352](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L278-L352)):
  - REQUEST keeps `len(view)//2 - keep_first - 1` tail events.
  - EVENTS keeps `max_size//2 - keep_first - 1`.
  - TOKENS keeps a suffix that brings the total below half the effective token cap.

  The leading `SystemPromptEvent` is always protected. Start and end snap to the next valid "manipulation index".
- A condensation is refused (`NoCondensationAvailableException`) if it would forget nothing, or less than `minimum_progress` of the view ([:423-434](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L423-L434)).
- Summary prompt: the system template is close to V0's (USER_CONTEXT/TASK_TRACKING/COMPLETED/PENDING/CURRENT_STATE/CODE_STATE/TESTS/CHANGES/DEPS/VERSION_CONTROL_STATUS) and says the events "will include previous summaries" ([prompts/summarizing_system.j2:1-47](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/prompts/summarizing_system.j2)). The events go in as `<EVENT>{{ event }}</EVENT>` blocks, followed by "Now summarize the events using the rules above." ([summarizing_events.j2:1-7](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/prompts/summarizing_events.j2)). Earlier summaries are therefore folded in as ordinary forgotten events, not through a separate `<PREVIOUS SUMMARY>` slot.
- The summary enters the view as a `CondensationSummaryEvent`, a `role="user"` text message with id `f"{condensation.id}-summary"`, inserted at `summary_offset` once forgotten IDs are removed ([OH1 event/condenser.py:51-96](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/event/condenser.py#L51-L96), [:120-132](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/event/condenser.py#L120-L132)).
- `hard_context_reset` summarizes *everything* after the system prompt. If the summarizer call fails, it shrinks each event string by ×0.8 and retries, up to 5 times ([llm_summarizing_condenser.py:354-405](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/llm_summarizing_condenser.py#L354-L405)).
- Truncation when the observation is created, V1 terminal: an observation longer than `MAX_CMD_OUTPUT_SIZE = 30000` is middle-truncated by `maybe_truncate(..., save_dir=full_output_save_dir, tool_prefix="terminal")` ([OH1 tools/terminal/definition.py:191-197](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-tools/openhands/tools/terminal/definition.py#L191-L197); [terminal/constants.py:18](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-tools/openhands/tools/terminal/constants.py#L18)).
  - Notice without a save directory: `<response clipped><NOTE>Due to the max output limit, only part of the full response has been shown to you.</NOTE>`.
  - Notice with a save directory: "...The complete output has been saved to {file_path} - you can use other tools to view the full content (truncated part starts around line {line_num})."

  - The save directory is `<conversation persistence_dir>/observations` ([OH1 conversation/state.py:407-411](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/conversation/state.py#L407-L411)).
- Any tool `TextContent` above `DEFAULT_TEXT_CONTENT_LIMIT = 50_000` is also middle-truncated when serialized ([OH1 llm/message.py:482-490](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/llm/message.py#L482-L490)).

### Inferences
- What stays verbatim:
  - SWE-agent `LastNObservations`: the system prompt, demonstrations, the instance template (problem statement), every assistant thought/action/tool-call entry, and the last *n* (to *n+polling−1*) observations.
  - V0 masking: everything except observations outside the window, with the window counted in events.
  - V0/V1 summarizing: the first `keep_first` events (V1 also always keeps the system prompt), the summary, and the recent tail. In V1 the tail is cut on safe boundaries.
- SWE-agent elision changes the prompt prefix every step, because the "last n" boundary moves. OpenHands rolling condensers change the prefix only at condensation events. That is the stated reason (V1 README §1-2) why summarization every half-window is cache-friendlier than per-step masking.
- Elision and summary placeholders are not preserved verbatim. SWE-agent shows a line count only; V0 shows `<MASKED>`; V1 shows an LLM summary. Truncation when an observation is created is lossy in all three, except that V1 terminal/browser output is saved in full to a file and the notice gives its path.

### Gaps
- I did not determine whether SWE-agent's per-step `trajectory` records (as opposed to `history`) keep the untruncated `step.observation` when `max_observation_length` triggers. `get_trajectory_data` saves both `trajectory` and `history`, but I did not trace the trajectory item's `observation` field. Unconfirmed.
- I did not verify, for V1 remote/sandboxed deployments, that the `persistence_dir/observations` file is reachable from the agent's own tools. Locally it shares a filesystem, but this is unconfirmed.

## Q2. What are the defaults, and which do the projects recommend or benchmark?

### Takeaway
Current SWE-agent ships **no** observation elision by default. The default processor is the identity, and the shipped default and recent Anthropic benchmark configs use only `cache_control`. The source says the classic `last_n_observations n=5` "is not always needed anymore", and it remains only in the 0.7-era, coding-challenge, human-demo and exotic windowed configs.

- V0 headless TOML without a `[condenser]` section uses LLM summarizing with config defaults: `max_size=100`, `keep_first=1`.
- V1 SDK `default_condenser()` uses `max_size=80, keep_first=4`. The class defaults are 240/2, and the V1 app-server path in the 1.6.0 tree constructs the condenser with those class defaults.

## Q3. Is there any per-tool or per-type treatment, or any model-requested retrieval of an elided observation?

### Takeaway
Per-type treatment exists in both projects but is limited:
- SWE-agent has tag-based keep/remove overrides, intended to be set by tool name, plus file-window and regex processors.
- OpenHands V0 has a browser-output-specific masker.
- V1 has per-tool size limits at creation time: terminal 30k, generic tool text 50k, editor.

Neither project lets the model retrieve an observation that was *elided or condensed*. V0 offers an optional, default-off `request_condensation` tool that asks for *more* forgetting, not less. The nearest thing to retrieval is V1's truncation notice, which names a file holding the full oversized output that the model can read with ordinary tools. That applies to truncation when the output is created, not to condensation.

## Q4. How does each preserve action/observation pairing, and what can the model recover?

### Takeaway
SWE-agent keeps pairing trivially. It rewrites only observation *content* and keeps the role (`tool`) and `tool_call_ids`, so every assistant tool call still gets its result, now holding the placeholder.

OpenHands V0 relies on a late repair step. It buffers assistant tool-call messages until every result is present, then filters out unmatched calls and results. Masking replaces the observation *object*, so this repair may silently drop the masked action in function-calling mode (an inference from the code, not verified). V0's `ConversationWindowCondenser` explicitly trims dangling observations.

V1 builds pairing into the forgetting algorithm. Four view properties (observation uniqueness, batch atomicity, tool-call matching, thinking tool-loop atomicity) define where cuts may be made, and the properties are enforced again when the view is rebuilt.

### Inferences
- What the model can recover from inside its context:
  - SWE-agent: that an observation existed, its line and image count, and the verbatim action that produced it. It can redo the action.
  - V0 masking: possibly nothing about a masked tool call in function-calling mode. The pending assistant message never completes, so the action would vanish while a bare `<MASKED>` user message remains. This inference is unverified and should be tested before anyone relies on V0 masking behavior.
  - V0/V1 summarizing: only what the summary LLM chose to record (TESTS, CODE_STATE, CHANGES and so on), plus V1's saved file for oversized terminal/browser output.
- V1's design makes condensation a planned, logged event whose cuts respect provider API rules. SWE-agent's design keeps provider-structure safety simple by never removing messages, only content.

### Gaps
- The V0 masking/function-calling interaction was not checked by running anything (study-only constraint). The JetBrains paper (below) tuned OpenHands masking with M=58, which suggests it was usable there. I did not confirm whether their OpenHands harness used function calling or a patched masker.

## Q5. Documented results: SWE-bench numbers, cost, failure modes

### Takeaway
SWE-agent's original ablation found that last-5 observation collapsing beat full history: 18.0% vs 15.0% on SWE-bench Lite with GPT-4 Turbo.

OpenHands' blog reports its summarizing condenser roughly halves per-turn cost at equal accuracy: 54% vs 53% on a SWE-bench Verified subset.

An independent JetBrains study ran both projects' styles inside SWE-agent. Simple observation masking (window 10) matched or beat LLM summarization on cost in 4 of 5 setups, with similar solve rates, and summaries lengthened trajectories. In OpenHands the masking window had to be re-tuned (M=58).

### Cited Findings
- SWE-agent paper (arXiv 2405.15793v3), Table 3, SWE-bench Lite (300), GPT-4 Turbo: "Last 5 Obs." (default) 18.0% resolved; "Full history" 15.0% (↓3.0); "w/o demo." 16.3% (↓1.7). Section 3: earlier observations are "each collapsed into a single line", and "all past error messages except the first are omitted" ([SWE-agent paper](https://arxiv.org/html/2405.15793)).
- OpenHands blog, Calvin Smith, 2025-04-09: "Up to 2x per-turn API cost reduction". Condenser 54% vs baseline 53% average on a SWE-bench Verified subset of unstated size. Cost scales linearly rather than quadratically "assuming events are of similar size". The trade-off is extra turns spent condensing. No numeric thresholds are given ([OpenHands blog](https://openhands.dev/blog/openhands-context-condensensation-for-more-efficient-ai-agents)).
- The OpenHands SDK guide repeats "up to 2x" per-turn savings and "equivalent or better performance on software engineering tasks" ([SDK guide](https://docs.openhands.dev/sdk/guides/context-condenser)).
- Lindenbauer et al., "The Complexity Trap: Simple Observation Masking Is as Efficient as LLM Summarization for Agent Context Management", arXiv:2508.21433v3, 27 Oct 2025, JetBrains Research ([arXiv](https://arxiv.org/html/2508.21433)). Setup:
  - In SWE-agent, observation masking used window M=10, described as best among tested windows, with placeholder text like "Previous 8 lines omitted for brevity".
  - LLM-Summary used an OpenHands-style prompt summarizing N=21 turns while keeping the last M=10 turns, triggered at 31 turns.
  - Turn limit 250; agent temperature 0.8, summarizer temperature 0.

  Table 1, SWE-bench Verified, solve / cost per instance:

  | Model | Raw | Masking | Summary |
  |---|---|---|---|
  | Qwen3-Coder 480B | 53.4% / $1.29 | 54.8% / $0.61 | 53.8% / $0.64 |
  | Gemini 2.5 Flash | 32.8% / $0.41 | 35.6% / $0.18 | 36.0% / $0.24 |
  | Gemini 2.5 Flash (thinking) | 40.4% / $0.56 | 36.4% / $0.24 | 31.4% / $0.25 |
  | Qwen3-32B | 17.0% / $1.12 | 15.0% / $0.55 | 16.0% / $0.50 |
  | Qwen3-32B (thinking) | 23.0% / $0.51 | 24.6% / $0.46 | 24.8% / $0.51 |

  Masking was cheapest in 4 of 5 setups. Summarization calls made up as much as 7.2% of instance cost. A hybrid (Qwen3-Coder 480B, Verified-50) was 7% cheaper than masking and 11% cheaper than summary.
- Failure modes in the same paper ([arXiv](https://arxiv.org/html/2508.21433)):
  - LLM-Summary lengthened trajectories: Gemini 2.5 Flash averaged 52 turns vs 44 with masking and 50 raw; Qwen3-Coder ran +15% vs raw and +13% vs masking. The authors' interpretation is that summaries "mask failure signals that would otherwise prompt earlier termination".
  - Critic-augmented summaries gave no solve gain and longer runs.
  - On short trajectories (≈15 turns) the summary rarely triggers.
  - Reusing M=10 in OpenHands "degraded performance drastically"; M=58 was tested instead.
  - Both strategies ignore staleness (e.g. a file modified after it was read).
- Source-level caveats from the projects themselves:
  - SWE-agent: `LastNObservations` "will break prompt caching" ([history_processors.py:106-108](https://github.com/SWE-agent/SWE-agent/blob/3ea751c087f32b16e039a2233dd6eefecef325d5/sweagent/agent/history_processors.py#L106-L108)).
  - OpenHands: summarizing "cannot take advantage of prompt caching… we'll pay for the cache writes but never get a chance to save on a read", so caching is disabled for the summarizer LLM ([OH0 llm_summarizing_condenser.py:167-171](https://github.com/OpenHands/OpenHands/blob/c5e0de8ecd85cef10e7808d57e9f939f3770ab9d/openhands/memory/condenser/impl/llm_summarizing_condenser.py#L167-L171)).
  - The V1 README describes regular condensation as a deliberate cache-rebuild tradeoff ([README.md:5-9](https://github.com/OpenHands/software-agent-sdk/blob/33d8aa29c3078d074799e2fbf5e847aeb2d71360/openhands-sdk/openhands/sdk/context/condenser/README.md)).

### Inferences
- The best evidence (one independent study, two projects' styles) says masking and summarization have similar accuracy and cost. Masking is simpler, needs no extra model call, and ends unproductive runs sooner. Summarization helps most on long runs and on whatever the summary keeps. Optimal window sizes are harness-specific (10 vs 58), because "window" counts different units: SWE-agent turns vs OpenHands events.
- The SWE-agent ablation (2024, GPT-4 Turbo, Lite) predates long-context models and prompt caching. SWE-agent's own later docstring and its default configs suggest the authors no longer find elision necessary for frontier models. That is the authors' opinion; I found no published re-ablation.

### Gaps
- I did not read the JetBrains paper's appendix configuration for the OpenHands experiment (condenser settings, function-calling mode); the fetch window did not cover it. It is also unconfirmed whether their SWE-agent masking placeholder is SWE-agent's built-in `LastNObservations` text or a modified one, since the paper's example wording differs from `Old environment output: (N lines omitted)`.
- The OpenHands blog's subset size, model, and condenser parameters are not stated in its text; its charts are images.
- I found no published numbers for V0's amortized, LLM-attention, structured or recent-events condensers, nor for SWE-agent's closed-window or RemoveRegex processors.
