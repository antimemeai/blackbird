## Delivery sequence and whole purpose

1. Separate generic VM/candidate owner and finite phase-checked action inbox.
   Fresh invocation scratch, bounded protected allocation/setup, typed constructors,
   coroutine budget/stop, no user finalizers/native loaders, native control outside
   Lua, source/view/input/query dependency checks. Own tests and one source review.
2. Native process-delivery observation and bridge over existing signal/interrupt
   reservation/dedup. Actual domain facts/references; accepted envelope survives
   view/reload. Missing acknowledgement stays unknown or is read by original key.
   No automatic retry, assumed kill success or second operation ledger. This unit
   must specify consumption/history before releasing inbox slots.
3. Actual /instrument and Ctrl-] adapter, an authored retained-result comparison
   over two pinned4096-byte source windows, and named Request interrupt for the
   frozen selected live job. Reuse CollectionInspector and sole Composer; native
   pin-A/pin-B controls remain local. Keep Enter as detail focus. Source reload/
   preview is async, effective handlers change only after successful preparation.
   Distinct raw literal/input/candidate/adoption/action links and prepaid admission
   preserve originals and last-good presentation. Root writes concrete adapter
   subplan and control bindings before implementing that owner.

These are conceptual units of one tranche; the first reusable-owner checkpoint
does not claim a working instrument, domain receipt bridge or every Unit2 feature.
No new production dependency, controller framework or device is selected.
