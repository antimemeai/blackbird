## Finding: context settlement acceptance differs from program activation

The proposed explicit actual-settlement flag correctly prevents replaying a
managed child accepted before fallible history pinning. It does not establish
that the pending program/policy/tool boundary was accepted. finish(true) can
accept a managed rejection first, then append the program boundary separately.
History pinning after the rejection can fail before that second append. Conversely,
no-pending finish can accept its program record and then fail history pinning.
CodingEngine's current catch clears all staged definitions on either exception,
leaving an accepted durable program boundary unapplied in the current engine.

Keep the local pending-settlement flag. Add a distinct narrow actual program-
boundary acceptance out flag, set only after the real program append or atomic
context/program append succeeds. Root turn activation uses that flag and performs
its already prepared noexcept swaps even if later history pinning fails. A
managed rejection alone cannot authorize those swaps. Failed prepublication
keeps the real pending proposal; accepted context settlement retires it without
reappend. No parse of accepted(result), guessed cursor or optimistic success
record can replace the actual separate acceptance boundaries.

Direct cuts must include (a) accepted managed rejection/history-pin failure
before separate program append: pending settlement completes, no new program
activation; (b) accepted context+program atomic publication then pin failure:
new Context head and native engine policy/program/tools match the durable packet;
(c) no-pending accepted program append then pin failure: native activation still
happens; and (d) actual prepublication failure: proposal intact, no activation.
Independently read accepted retained packets and live native state, then reopen
without any repeated semantic append or dispatch. One exact history closure
allocation cut bears directly on each branch, not a hypothetical failure flag.

## Finding disposition

The Context and turn subplans now name context_settlement_accepted,
boundary_program_accepted and activation_applied separately. Only actual program
acceptance authorizes the already prepared native swaps, including after a
later history-pin failure. Managed rejection alone retires the pending child.

result is claimed by this design resolution.
