# Provider/auth: ONE code/oracle attack

Root inspected raw_auth capture/budgets, ProviderAuth and OAuth owners, Codex
private file/RPC boundaries, auth/application linkage and standalone native
environment/signal ownership against the reviewed subplan and actual fixture.
Latest source/tests are idle; four affected business/raw targets pass. This is
the ONE code/oracle attack, followed by finding correction and direct recheck.

## Finding

The private-surfaces fixture skips both full references in1610 before checking
status/branch, and skips each scalar's lane before matching action ordinal.
The Codex fixture checks the15-site private sequence and the separate actual
auth/application1612 pair, but not private operation request/return identities
or operation tags. A swapped private request/return Ref can pass those oracles.
Replace those skipped-field checks with exact actual action R and request R,
expected operation tags, native result variants, one return per begun operation
and no fabricated Error fields for unknown exceptions. Check full action/lane
identity for scalar expectations too. Private bytes remain excluded: do not
capture secrets merely to strengthen the oracle. Recheck the affected fixture;
no second review panel.

## Reviewed source

Action construction holds a separately split51-byte terminal before BEGIN;
start's DATA failure is caught by the already constructed owner. Browser child
splits use the same lane and finite parent bank; standalone CLI children link
to their command without borrowing its independent bank. Save request/return
credit precedes writes, and stage7 correctly records post-rename directory-sync
failure without rolling back the new credentials. Device scalar emission copies
existing native acquisitions/calculations; instrumentation does not call clocks
or compute new durations/retry values. Worst device-poll slow-down and ready
branches fit12 scalar slots; owned resolution fits its9/7 variants and two save
attempts, including the existing refresh-unknown recovery.

Private credentials, token/code/JWT/file/RPC payloads and credential-bearing curl
configuration remain excluded from metrics. Valid public add-provider arguments
are copied before existing URL trimming; invalid credential-bearing URLs fail
validation before descriptor capture. Auth1612 copies actual resolution and
application references. Private native child paths deliberately use whole
operation request/return boundaries rather than opting into application payload
capture.

Standalone bootstrap owns a separate native40-byte environment header with
exclusive directory publication, preserves a published identity after sync
failure, and refuses corrupt/incomplete existing identity. Credential-ancestor
exclusion uses native directory metadata rather than opening the private Store.
Mac F_GETPATH obtains the actual held private root path; before/after Runtime
setup checks compare actual dev/inode/uid/mode and retain the original root FD
through descendants. Its stable owned-directory limitation is explicit; no
hostile same-user namespace sandbox or rename-during-setup continuity is claimed.
Linux uses the actual held FD portal. Sticky signal descriptors remain live
through business work and are unpublished before close/mask restoration. No
new source defect is asserted in this review.

## Finding disposition and affected recheck

The owning fixture now decodes and checks both complete action/request references
for every private HTTP and whole-operation return, the operation tag at each
begin, and exact native result bodies. Each begun exchange is removed only by
its one matching return; duplicate, missing or swapped returns fail directly.
HTTP cases include returned status200/400, original io/ECONNRESET, and unknown
exception with no invented Error/status fields. Scalar checks include the actual
lane epoch. Codex's five file/RPC pairs now compare literal complete request and
return bodies, actual begin ordinals, operation tags and native branch variants,
in addition to the existing resolution/application link and secret exclusion.

The affected provider_auth_raw fixture passes after a single-worker debug
rebuild (context/provider-auth-green.log). Narrow clang-tidy of raw_auth.cpp and
provider_auth_raw_test.cpp finishes without diagnostics; clang-format dry-run
and the relevant diff check pass. The helper's unnecessary iterator copy was
changed to a const reference. No new auth review panel or production hook change
was introduced to resolve the oracle finding. Root owns integrated qualification
and delivery.
