# F2 native leaf executor pool

2026-10-15. Written before source changes. All work is confined to this workflow checkout; the root owns build/CMake, journal, issues and commits.

Build one bounded owned executor for leaf native work. The workflow owner calls submit, cancellation, drain and shutdown. A retained admission callback runs on that owner after input/task/completion storage is reserved and before work becomes visible to a worker. Workers execute only the supplied leaf callable, write its exact result or exception into its reserved completion slot, and notify the owner. They never invoke retention, publication, Lua or context callbacks.

Use existing typed invocation/attempt IDs plus generation-checked domain handles. Immutable source, context and input bytes use shared const ownership. Results retain success/failure/cancelled/unknown, actual invocation and cancellation-request observations separately. Queued cancellation prevents invocation. Running cancellation requests cooperative stop; a successful late return remains success. Arbitrary thrown exceptions are preserved exactly and classified unknown because the executor cannot infer outside effects.

Layer-one repair: a shared const `ByteBuffer` alone permits public reassignment through a retained mutable alias. `WorkflowExecutorPayload` instead acquires one byte copy through its private factory and deletes copying/moving/assignment of the payload object. Subsequent task/history references share that same immutable object. Compile-time oracles reject mutable construction/assignment; a direct acquisition oracle mutates the external source bytes after freezing and checks the retained payload remains exact.

Allocate the live slot array, free-slot list and intrusive ready/completion queues before admitting work. Each task owns its result slot and stop source. Completion queue insertion moves no allocating payload and cannot fail from a full result queue. Finished work keeps its live capacity until the owner acknowledges successful delivery; a failed/throwing owner callback leaves it drainable. Cancelled queued tasks are removed from the ready queue before their completion is published. No wait, join, user callable, stop callback or owner callback runs under the executor mutex.

Parameterize runnable workers and live-task capacity. Use owned `std::jthread` workers; shutdown closes admission, terminalizes queued work, requests running stop without a mutex and joins every worker. Completions remain available to drain after shutdown. Noncooperative native leaf code can delay shutdown; do not report it stopped. Owner thread/reentry validation rejects worker control, and stale handles cannot cancel a reused slot. Coordinators and dependency waits belong to the root scheduler, which parks continuations; they are forbidden inside the leaf callable.

Direct checks use gates and independent live counters: two actual simultaneous leaves, worker/capacity bounds, exact bytes/exception retention, admission callback ordering/thread, queued cancellation with zero invocation, running cancellation with honest late success/unknown, stale handle isolation after slot reuse, rejected off-owner controls, completion retry after failed publication, and joined shutdown with all results drainable. Tests are authored before implementation; the root runs builds and diagnostics in the shared build-writer lane. No arbitrary sleeps establish concurrency. Bounded fault timeouts only prevent a broken fixture hanging the campaign.

Grounding: the reviewed concurrent/durable design's physical-worker parking and request/custody separation; the fresh Pi Durable scheduler's completed-versus-settled ownership; Oh My Pi's exact-generation stale-control/tombstone lesson; Hermes's abandoned-worker join limit; existing foundation domain/generation handles and Participants owner-only callback boundary. No dependency or third-party code is adopted.

After implementation, one independent code attack and one focused recheck cover concrete findings. No third assurance layer, mutation run or unrelated source edits.
