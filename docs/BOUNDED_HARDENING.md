# Bounded remediation: two layers, never three

Operator instruction2026-10-07: hardening must always be bounded.
Layer1: remediation tasks, fix. Layer2: recheck, fix. Never layer3.
This supersedes older language allowing repeated tribunals or progressively
broader qualification before a unit can finish. It does not excuse real defects.

Operator2026-10-11 rejects imposing fresh arbitrary campaign timers. Bound work
by concrete defects and the two layers, and finish the authorized delivery.
The numerical allowance in the historical capacity unit below applies to that
unit; it is not a universal stopping rule or permission to abandon current work.

## The rule in ordinary Arco work

Before hardening, name the concrete defects, affected behavior, useful delivery,
direct oracles and deliberate resource use in the existing work note. A short list is
enough; no separate certification ledger. Source/literature inform the fix and its
oracle, not an additional chain of evidence about evidence.

Layer1 implements the listed repairs and runs the direct checks that show the
actual behavior. Consequential independent review may identify defects in this
changed unit. Do not expand the unit to unrelated improvements or run all old
checks merely because they exist.

Layer2 rechecks the changed behavior/findings once. Fix valid defects it exposes
and rerun the same affected direct oracle where the fix requires it, within the
same allowance. Never review the review, certify the recheck, add a fresh tribunal
for confidence, restart all host/profile checks without a relevant change, or reset
the allowance under a new branch/session/task label.

A direct test rerun after a real fix is work within layer2, not a new assurance
layer. Persistent failure does not buy infinite retries. At the allowance boundary,
retain the findings and leave the unsafe candidate inactive/revert that candidate;
choose independent useful work or report the specific block. Only explicit new
operator scope can reopen that bounded task. No approval of ordinary tools added.

Delivered correctness and operational limits are recorded plainly. No “certified”
status, new judge, model confidence gate, or correctness-by-budget-expiry claim.

Layer1 remaining defects are the actual review findings:

1. Prospective cancellation must fit max_payload and max_batch_bytes, not just
   aggregate journal byte/record credits.
2. Reserved cancellation must cover the longer turn_interrupted linkage output
   (including its duplicate presentation/original encoding).

Retain the already implemented workflow overflow, sticky capacity, nested attempt,
partial capture/unknown settlement and cancellation behavior. Test the two concrete
findings directly. Complete the existing affected coding/context/retained_state
checks on the changed host profiles; already-green unrelated checks stay settled.

Layer2 is ONE focused recheck of those fixes and the integrated stop/settlement
claim. Fix findings within that layer; no new panel/consensus or general core audit.
One actual native replacement and ordinary request establishes activation. Use the
existing explicit fresh-session path for capacity continuation, with honest unknown
lineage and no old-effect replay. Do not require an unattended recovery platform or
full historical replay optimization to accept this scoped behavior.
